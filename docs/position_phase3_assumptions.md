# Position Phase 3 - Execution and Calculation Assumptions

## Purpose

Position Phase 3 defines how an executed trade affects an existing
Position and how the Position's financial values are updated.

The approved project specification does not prescribe exact formulas
for average price, realized P&L, unrealized P&L, or market value.

Therefore, the following rules are documented as implementation
assumptions for the backend.

## 1. Trade Quantity

### BUY

A BUY trade increases the Position quantity.

New Quantity = Existing Quantity + Executed Quantity

### SELL

A SELL trade decreases the Position quantity.

New Quantity = Existing Quantity - Executed Quantity

A SELL quantity greater than the existing Position quantity is rejected.

If the resulting quantity becomes zero, the Position is marked CLOSED.

## 2. Average Price

The Position uses a weighted-average acquisition price.

For a BUY trade:

New Average Price =
    (
        Existing Quantity * Existing Average Price
        +
        Executed Quantity * Executed Price
    )
    /
    New Quantity

For a SELL trade, the existing average price remains unchanged while
the Position remains open.

## 3. Realized P&L

For a SELL trade:

Realized P&L from Trade =
    (Executed Price - Existing Average Price)
    * Executed Quantity

The resulting realized P&L is added to the Position's existing
realized P&L.

BUY trades do not directly realize P&L.

## 4. Unrealized P&L

For an open Position:

Unrealized P&L =
    (Current Price - Average Price)
    * Quantity

If Current Price is unavailable, unrealized P&L is not recalculated.

When a Position is fully closed, its remaining unrealized P&L is set
to zero.

## 5. Market Value

When Current Price is available:

Market Value = Current Price * Quantity

If Current Price is unavailable, Market Value remains unavailable.

## 6. Position Closing

When a SELL trade reduces the Position quantity to zero:

Quantity = 0
Position Status = CLOSED
Closed At = Current UTC Timestamp
Unrealized P&L = 0

Realized P&L is retained because it represents the accumulated
profit or loss generated by completed SELL transactions.

## 7. Timestamp Handling

Trade-driven Position changes update:

last_updated_at = Current UTC Timestamp

When a Position is closed, the same UTC timestamp is used for
closed_at.

## 8. Scope and Limitation

These calculation rules are implementation assumptions because the
approved project specification does not define an accounting method
or exact Position calculation formulas.

The implementation uses weighted-average cost and does not implement
FIFO, LIFO, tax accounting, or other accounting methodologies.

Any future change to these assumptions should be treated as a
domain-rule change and should be reflected in the tests and
documentation.
